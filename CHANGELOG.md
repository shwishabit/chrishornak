## 2026-06-08 (cont.) — Fixed: audit "couldn't reach" false-positive on sites that are actually online
- **Fixed: the audit reported `We couldn't reach <site>` for live sites** (caught on f0rmless.com — apex `308 → www`, www `200` in <1s, exact `SiteCheck/1.0` UA gets through). Root cause: `safeFetch` returns null on the main page fetch during a transient Vercel-edge blip (datacenter-IP request challenged/reset while browsers are served cleanly); the live audit reproduced clean, so it had self-healed. **Fix:** new `fetchPageWithRetry()` in `api/audit/route.ts` retries the page fetch **once, only on a fast failure** (`<2s` = transient throw, not the 8s timeout) with a shorter 4s budget + 250ms backoff, so worst case stays under Vercel's ~10s function limit. Aux fetches (robots/sitemap/llms) stay single-shot. tsc 0 / build 0 / live audit re-verified post-deploy. Site `aa54d56` (pushed to `shwishabit/chrishornak`), parent pointer `f74abc7`.
